# Locked persona sits + outcomes (conjure method)

**Archive (prompts + full sits + outcomes + interpretation note):** [`persona-sits/`](./persona-sits/)

**Method:** Conjure-only sits → parent decomposes outcomes.  
**Guest/BC:** validated external conjure. **Operator/Worker:** conjure agents (same vigor).  
**Locked:** No Worker↔Client free messaging. Meeting **pre-call packet** on the meeting. Escrow sacred. Activity vanity refused.

Task complete when Register click-throughs inhabit these outcomes.

---

| `client-meeting-packet` | Meeting delivery + pre-call packet | As a Tally business client, I can receive a calendar meeting with concise pre-call notes (who, company size, stated pain) and an escrow release receipt for that meeting — so that under steady motion I can take the call without living in the app. |

## 2. Tally Operator

### Sit (compressed)

Incentive: funded vessels + compounding trust; judgment checkable within weeks.  
Success pre-fund: fund without haggling price down (dossier answered objections).  
Success post: meetings match what was promised.  
Unforgivable: enrich/price theater.  
No-app: DB opinion → price from ACV/fit → live re-price on call → escrow lawyer → written brief to Worker.  
Gates locked: dossier→price, verdict→enrich, fund→launch, launch→Worker.  
Low motion: need Worker-not-started vs not-landing; refuse activity as progress.  
Stay if live re-analyze, no unfunded launch, escrow untouchable by Operator, honest post-launch glance.

### Outcomes — Operator

| Id | Label | Statement |
|----|-------|-----------|
| `operator-core` | Core | As a Tally Operator, I can create, evaluate (dossier as pricing reason), enrich after verdict, invite, and launch only after fund — so that a client can join/fund a priced meeting vessel and a Worker can pick up only what is funded and launched. |
| `operator-market-scan` | Market Scan | As a Tally Operator, I set criteria and run a scan — so that I have a pre-screened company to open in Evaluate. |
| `operator-dossier-price` | Dossier as pricing reason | As a Tally Operator, I open a company dossier that states why this company and what justifies $/meeting — so that I can defend the price live and the client funds without haggling from confusion. |
| `operator-reanalyze` | Live re-analyze | As a Tally Operator, I can edit and re-run the dossier fast enough on-call — LOCAL — so that I keep the room. |
| `operator-enrich-after-verdict` | Enrich after verdict | As a Tally Operator, I enrich only after a fund-likely verdict — LOCAL — so that enrich cost is not ops spend on a no. |
| `operator-invite` | Invite | As a Tally Operator, I invite NB or BC into a vessel I created — so that they can fund without creating campaigns. |
| `operator-launch-after-fund` | Launch after fund | As a Tally Operator, I can launch only when funded — so that Workers never see unfunded vessels. |
| `operator-handoff-rules` | Handoff rules of engagement | As a Tally Operator, I pass locked meeting-qualification rules with the launched campaign — so that Worker and client share one definition of what counts. |
| `operator-post-launch-glance` | Post-launch glance | As a Tally Operator, I can see honest meeting progress (booked / N), not activity — LOCAL — so that I know when to re-engage or fix sizing. |

## 3. Tally Worker

### Sit (compressed)

Incentive: paid on qualified meetings that survive scrutiny — not activity.  
Success: clean meetings that release; failure: disputed garbage after effort.  
No-app: locked rules, list, phone, calendar proof, handoff of who/company/when for escrow.  
Queue must be ready-only; claim exclusive; log is case for pay; client gets meeting context not a chat relationship.  
Stuck: honest release back to pool; refuse fake qualification.  
Stay: fast fair release, locked rules, disputes not auto-client-favored, ready queue.

### Outcomes — Worker

| Id | Label | Statement |
|----|-------|-----------|
| `worker-core` | Core | As a Tally Worker, I can pick up a launched campaign, begin it, manage outreach against locked rules, and track booked meetings — so that business clients receive qualified meetings and escrow can release. |
| `worker-log-meeting` | Log booked meeting + packet | As a Tally Worker, I can log a booked meeting with who, role, company, time, and stated pain — so that escrow has proof to release and the client gets a pre-call packet without messaging me. |
| `worker-pipeline` | Claimed pipeline | As a Tally Worker, I can see campaigns I've claimed as booked / N — LOCAL — so I know where each stands. |
| `worker-react-stop` | React to stop/reclaim | As a Tally Worker, when a client stops or reclaims, I can see it and stop working — LOCAL — so I don't grind a dead campaign. |
| `worker-release-dead` | Release dead claim | As a Tally Worker, when a list won't move, I can return the campaign to the available pool — LOCAL — so dead inventory doesn't trap anyone. |
| `worker-dispute-visibility` | Dispute visibility | As a Tally Worker, I can see if a logged meeting was approved or disputed — later — so I learn without becoming the client's account manager. |

## Forced shared objects (click-through must show)

1. Locked campaign rules (who counts, length, seniority, $/meeting, N)  
2. Escrow terms (hold, per-meeting release, reclaim)  
3. Meeting log + pre-call packet  
4. Escrow release receipt / held vs released  
5. Launch-after-fund gate (Worker queue)  
6. Conversion receipt (Guest → BC)  
7. Low-motion honesty + reclaim (not activity)  
8. Honest booked / N (not %)

**Explicitly not building:** Worker↔Client inbox, CS cheerleaders, activity vanity, client-created campaigns.
