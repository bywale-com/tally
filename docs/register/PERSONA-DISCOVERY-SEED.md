# Persona outcome discovery — shared seed

Use this as the only product truth. Sit inside your assigned persona. Push agenda and needs to the edge. Do not invent a second product.

## Why this world exists

Tally is a **pay-per-booked-meeting** sales arbitrage platform. Buyers want meetings. Money is held **escrow-style** (Escrow.com later). Campaigns are **Operator-priced vessels** (e.g. N meetings × price set ahead), not client-authored.

## Locked mechanics

- Operator selects company from existing DB; **Evaluate dossier** = why selected + basis to **price the meeting** (ACV/fit). Edit / re-analyze must be fast enough on-call (agentic recalculation later).
- Verdict → only then Enrich (strong prediction they will fund).
- **Business clients never create campaigns** — Operator creates first and later campaigns.
- First fund = client puts money up for that campaign as defined → then Operator can **launch**.
- Escrow: money held for a period (vesting/hold so work can happen); release **per booked meeting** (one at a time); Escrow.com owns disputes; Tally toggles via API later.
- Worker produces booked meetings. V1 = one seeded Worker; multi-worker onboarding is thinkable but not V1 build.

## Living personas

Operator · Non-business Client (Guest) · Business Client · Worker. Agent deferred.

## Current Core (extend / gap-fill — do not replace the spine)

- Operator: create, evaluate, enrich, invite NB, invite BC, launch — so client can join/fund and Worker can pick up.
- NB: accept, walk, first fund → become BC — so Worker can begin/manage the campaign funded.
- BC: join/fund, notified of progress, respond, stop/recollect — so Worker can begin/manage while client stays informed.
- Worker: pick up launched, begin, manage, track — so BC notified of progress.
